# 界面文案与翻译

`web/locales/messages.json` 是完整消息的唯一词条目录。词条使用稳定 ID；中文源文、英文及其他语言译文放在同一条目，动态内容采用 `{count}` 等具名参数。语言来自 CPA，不设置独立语言开关。

```js
t('history.deleted', {count: result.count})
```

静态标签使用声明式属性，切换语言时无需重建表单：

```html
<span data-i18n="brand.subtitle">Account Warmup &amp; Scheduling</span>
```

- 新文案优先添加语义 ID，再调用 `t()` 或设置 `data-i18n`。修改已有词条时保留 ID，同步审查所有译文。
- 参数只传递数据，不能将一句话拆成多个词条拼接。译文可以调整参数顺序，不能添加或丢失参数。
- 默认语言为 CPA 当前语言；缺少该语言的完整词条时回退完整英文。英文为必填，禁止逐词替换、机器拼接和中英混排。
- 现有模板通过完整消息兼容层迁移：只匹配完整消息或完整参数化消息，不匹配句子中的词语。兼容层索引来自同一目录，不另建替换词典。
- 用户保存的账号名、任务名、分组名与描述必须使用 `translate="no"` 或已有对应组件；不把保存的数据写入翻译目录。输入框值不经过翻译。新建默认名称可按当前语言生成，保存后按用户数据处理。
- 新增 `data-i18n` 文本请用纯文本节点；含链接、图标或富文本时将翻译节点与结构分开。不要将未转义的用户输入拼入 HTML。

运行 `python3 scripts/build_web.py` 或 `python3 scripts/ci.py`。构建检查现有模板文案覆盖、显式键引用及各语言参数一致性；新增或修改中文源文却未更新目录会直接失败。`tests/i18n.test.cjs` 覆盖整句翻译、参数、回退、语言来回切换和用户内容保护。

数量词条可通过 `plural.parameter` 指定数量参数，`plural.en.one` 提供单数形式；运行时使用 `Intl.PluralRules` 选择对应形式，其他情况保留该语言默认译文。所有形式也会校验参数。
